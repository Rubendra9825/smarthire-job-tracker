SmartHire – Interview Cheat Sheet

The 30-Second Elevator Pitch:
"SmartHire is a full-stack, secure job application tracking system. It allows users to create accounts, log in securely, and manage their job hunt by performing CRUD (Create, Read, Update, Delete) operations on their job applications. It features a custom-built responsive UI and tracks application statuses securely."

1. The Tech Stack

This project is essentially a modified MERN stack (using Vanilla JS instead of React to prove fundamental knowledge).

  • Frontend (Client): HTML5, Custom CSS3 (Glassmorphism design), and Vanilla JavaScript (ES6+).
  • Backend (Server): Node.js and Express.js.
  • Database: MongoDB (hosted on Atlas) using Mongoose as the ODM.
  • Security/Auth: JSON Web Tokens (JWT) for sessions, and bcrypt.js for password encryption.

2. How the Architecture Works

If someone asks: "Explain the flow of data in your app."

Your Answer:

"The app relies on a Client-Server RESTful Architecture.
1. The Frontend consists of static HTML/JS files. When a user clicks 'Save Application', the Frontend JavaScript uses the fetch() API to send an asynchronous HTTP POST request down to the backend.
2. The Backend (Express on Node.js) receives this request. It routes the request to a specific Controller function.
3. The Controller uses Mongoose to validate the data and save it directly into the MongoDB cloud database.
4. The database replies with success, the backend sends a JSON response back to the frontend, and the frontend dynamically updates the UI to show the new application without reloading the page."

3. Technical Deep Dives (Common Interview Questions)

Q: How did you handle user authentication and security?

Your Answer: "Authentication is completely stateless using JWT (JSON Web Tokens). When a user signs up, I hash their password using bcrypt so the raw password is never saved in the DB. When they log in, the server generates a signed JWT and sends it to the frontend. The frontend saves this token in localStorage. For every future request, the frontend attaches that token in the Authorization header. The backend has custom middleware that catches every request, verifies the token's signature, and ensures the user only sees their own private data."

Q: Why did you use Vanilla JavaScript instead of React or Vue?

Your Answer: "I purposefully used Vanilla JS to strengthen my fundamental understanding of the DOM (Document Object Model) and browser APIs. I built my own state management, my own custom asynchronous `apiFetch` wrapper, and handled custom UI rendering manually. Taking this route ensures I actually know how the web works under the hood rather than just relying on framework magic."

Q: How is your backend codebase structured?

Your Answer: "It strictly follows the MVC (Model-View-Controller) design pattern to keep the code organized and scalable:
- Models: Define the MongoDB shape/schema (User schema, Application schema).
- Routes: Define the URL endpoints (e.g., POST /api/applications).
- Controllers: Contain the actual business logic."

Q: Are there any challenges you faced and overcame?

Your Answer: "One major challenge was network reliability and local DNS firewall blocks preventing connection to MongoDB Atlas. To ensure I could continue developing and testing the front-end regardless of my internet connection, I implemented a robust local testing script using mongodb-memory-server which spins up a mock database instantly in-memory, ensuring development is never blocked."

4. Quick Mental Checklist

Before you talk about the project, remember these keywords:

  • CRUD: Create, Read, Update, Delete (You implemented all 4).
  • Stateless Auth: Because JWTs don't require the server to store sessions locally.
  • Client-Side Rendering (CSR): Because your JS injects HTML into the page dynamically.
  • RESTful API: Because your backend uses standard GET, POST, PUT, DELETE endpoints.
